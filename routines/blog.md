FORMAT EXPERIMENT
Posts have a `format` in their frontmatter: guide (evergreen how-to answering a real search question), trending (explainer of a business, startup or geopolitics story in the news this week, category Explained), comparison (honest "best apps / best ways / alternatives" list, fair to competitors, with a one-line disclosure that we make Qrio), brand (about Qrio; use rarely). The weekly SEO check compares formats on search clicks, read depth and Download clicks, and writes its findings to /Users/user/Documents/Claude/Projects/Explainer/seo-weekly/ (newest file = latest). Decide the format for this run like this:
- If the newest weekly report has a section "Next week's post mix" (or a clear format recommendation), follow it.
- Otherwise rotate by weekday: Monday = guide (first `todo` queue row that is a guide), Wednesday = trending (pick the most-searched business, startup or geopolitics story in India this week that Qrio's audience cares about; check Google Trends India and news; avoid topics already covered in content/blog and content/archive), Friday = comparison if a `todo` comparison row exists in the queue, else guide.

STEPS
1. Read content/blog-plan.md in full. It holds the goal, the reader, the editorial rules and the queue. Follow the rules there exactly. Read the newest file in seo-weekly/ if one exists.
2. List the files in content/blog/. If an older post still has status: draft, mention it in your final message, but do not publish it.
3. Choose the post using FORMAT EXPERIMENT above. For queue posts, take the matching `todo` row. For trending posts, add a new row to the queue for it (status todo) before writing.
4. RESEARCH FIRST with WebSearch and WebFetch. Open the real pages. Prefer primary sources (the paper, the report, the official site, the company filing). Use at least four sources you actually opened. Cross-check every important fact across at least two sources. Never write a number, study result or quote from memory. If a page blocks you (403), find another source or leave the claim out. Because nobody reviews before publishing, be strict: if a claim has only one source, either drop it or attribute it clearly to that source. Check what currently ranks on Google for the target search and make this post clearly more useful than those pages: answer the question faster, add something they miss (a table, a comparison, an India angle, a clear "what it means for you"). Be fair to competitors.
5. WRITE the post as content/blog/<slug>.md with this frontmatter: title (no full stop at the end, aim for 60 characters or fewer), description (120 to 160 characters), date (today, YYYY-MM-DD), category (Doomscrolling, Staying informed, Explained or Behind Qrio), format (guide, trending, comparison or brand), status: draft, and faq (3 or 4 items with q and a, each answer under 60 words). Body rules: no H1 in the body, open with a direct answer in the first two sentences, headings that match real questions, plain warm voice, short sentences, 1,200 to 1,900 words, inline source links, at least one table or list, end with a `## Sources` list. Internal links: link to 2 or more related published Qrio posts (/blog/slug) and, where genuinely relevant, 1 or more stories (/explainers/slug, check content/archive for matching topics). Link only to posts whose status is published. If Qrio is mentioned, add a one-line disclosure that we make it. Do not use em dashes. Never end a heading or title with a full stop. Never use the words learn, educational, explainer, knowledge, upskill, intellectual or Reels (words inside URLs are fine). Be careful with health topics: say plainly when research is only correlational, and never give medical advice beyond suggesting a doctor or counsellor. Trending posts: no clickbait, say when facts are still developing, and include the date things happened.
6. CHECK: run `npm run blog:check <slug>` in the project folder and fix everything until it prints PASS.
7. PUBLISH:
   a. Change the post's frontmatter to `status: published` and set the queue row in content/blog-plan.md to `published`. Run `npm run blog:check <slug>` again and confirm PASS.
   b. Run `git status`. Make sure you are on `main` and run `git pull --ff-only` first. If the pull fails or the branch is not main, stop, leave the post as a draft (status: draft, row `drafted`) and report.
   c. Run `npm run build`. If the build fails, revert the post to status: draft, set the row to `drafted`, do not commit, and report the error.
   d. Stage ONLY the new post file and content/blog-plan.md, by exact path (`git add content/blog/<slug>.md content/blog-plan.md`). Never use `git add -A` or `git add .`. Never stage other drafts, .claude/ or anything else.
   e. Commit with the message `Publish blog post: <short title>` and end it with the line `Co-Authored-By: Claude <noreply@anthropic.com>`. Then `git push origin main`. Never force-push.
   f. Wait about 3 minutes, then check https://www.qrioapp.in/blog/<slug> loads (curl -L, status 200 and the title appears). If it is not live after about 10 minutes, report that in the final message. Once it is live, run `node scripts/indexnow.mjs` from the qrio-web folder so Bing and other IndexNow engines pick up the new post right away (it prints the number of URLs submitted and an HTTP status; 200 or 202 is success).
8. FINAL MESSAGE (this is what Ashish reads): the post's title, live URL, format, description and category; why this format and topic were chosen; the commit hash; a short summary of the post (not the full text); (a) the key claims with the source you verified each against; (b) anything you could not verify and left out; (c) any older drafts still unpublished. If anything stopped the publish, say clearly that the post was NOT published and why.

Do not touch any other file than the new post and blog-plan.md. Do not install packages.
